Logarithmic growth

Чому O(log N) росте так повільно.

Логарифм відповідає на питання: до якого степеня треба піднести основу, щоб отримати певне число? У coding interviews це дає дуже корисний mental model для алгоритмів, які щоразу різко зменшують problem space.

Binary searchHalvingBalanced treesHeap operations
logb(x) = y ⇔ by = x
Логарифм — це просто інший спосіб поставити питання про степінь. Для binary-search-style задач зручно думати про base 2.
01 · Definition

Що означає логарифм?

Твоя вихідна формула — це вся ідея. Решта лише способи її інтерпретувати.

logb(x) = y  ⇔  by = x
1
b — baseЧисло, яке ми підносимо до степеня.
2
x — resultЧисло, яке хочемо отримати.
3
y — answerСтепінь, до якого треба піднести base.
log₂(8) = 32³ = 8
log₂(32) = 52⁵ = 32
log₁₀(1000) = 310³ = 1000
02 · Interview mental model

Чому в інтервʼю ми думаємо про log₂?

Коли алгоритм кожним кроком ділить problem space приблизно навпіл, кількість кроків визначається тим, скільки разів N можна поділити на 2 до 1.

Binary-search intuition2ʸ = NТому y = log₂(N). Якщо N подвоївся, y збільшується лише на 1.
Big O nuanceO(log N)У Big O base зазвичай не пишуть: зміна base лише множить логарифм на constant factor. Для halving алгоритмів base 2 — найзручніший mental model.
03 · Doubling explorer

Подвоюй input і дивись, що відбувається.

Для простоти N тут завжди дорівнює 2ᵏ. Це робить різницю між linear і logarithmic growth дуже наочною.

N = 1,024
O(N)1,024Умовних операцій при linear pass.
O(log N)10Умовних кроків при halving.
Головний mental model: коли N подвоюється, O(N) приблизно подвоює роботу, а O(log N) додає лише один крок.
04 · 1,000 elements

Чому 1,000 елементів — це приблизно 10 кроків?

Бо 2¹⁰ = 1,024. Тобто log₂(1,000) ≈ 9.97.

Linear~1,000Один linear pass по 1,000 елементах — приблизно 1,000 units of work.
Logarithmic~10Halving-style search — приблизно 10 кроків, бо 2¹⁰ ≈ 1,000.

06 · Interviews

Де логарифми зʼявляються на інтервʼю?

Шукай pattern: problem space або tree height зменшується/росте експоненційно відносно кількості кроків.

O(log N)

Binary Search

Кожен comparison відкидає приблизно половину пошукового простору.

O(log N)

Balanced BST

Search / insert / delete залежать від height; у balanced tree height ≈ log₂(N).

O(log N)

Heap

Insert і remove можуть рухати element по tree height, а height binary heap — O(log N).

depth ≈ log N

Divide & Conquer

Recursion depth часто logarithmic, якщо input ділиться навпіл. Загальна time complexity залежить ще й від роботи на кожному level.
