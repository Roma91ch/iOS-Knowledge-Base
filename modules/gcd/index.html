Grand Central Dispatch

Queue work. Let the system schedule threads.

GCD — системна abstraction над thread management. Ти описуєш work items, queue semantics, QoS і synchronization points; система керує pool of threads і вирішує, де фактично виконувати роботу.

Queue ≠ thread

→

Core idea: queue визначає ordering / concurrency semantics, але за винятком main queue не прив’язана до конкретного thread. GCD використовує system-managed pool of threads.
02 · Serial vs concurrent queues

Queue type відповідає на питання: чи можуть work items overlap?

Serial queue

Один work item за раз. Зручно для protecting mutable state або enforcing order.

A ━━━━━ B ━━━━━ C ━━━━━

Concurrent queue

Кілька work items можуть виконуватись concurrently. Start order пов’язаний з queue ordering, completion order не гарантований.

A ━━━━━━━━━ B ━━━━━━━ C ━━━━━━━━━
let serial = DispatchQueue(label: "com.app.state")
let concurrent = DispatchQueue(label: "com.app.processing", attributes: .concurrent)
03 · Main and global queues

Main queue

Serial queue bound to the app’s main thread. UI work традиційно dispatch-иться сюди.

DispatchQueue.main.async {
    label.text = "Done"
}

Global queues

System-provided concurrent queues backed by the global thread pool.

DispatchQueue.global(qos: .userInitiated).async {
    compute()
}

Custom queues

Дають власний label, QoS, serial/concurrent semantics, autorelease policy та target queue configuration.

04 · sync vs async

Це про caller waiting, а не про serial vs concurrent

syncasync
CallerБлокується до завершення work itemПовертається одразу
Queue typeМоже бути serial або concurrentМоже бути serial або concurrent
ResultМожна повернути прямо з closureРезультат приходить пізніше / через інший mechanism
let value = queue.sync {
    calculateValue()
}

queue.async {
    calculateAndStore()
}
Classic deadlock: synchronous dispatch на queue, яка вже виконує caller і не може почати новий item. Найвідоміший випадок — DispatchQueue.main.sync з main thread.
05 · QoS

Priority intent, не гарантія часу виконання

.userInteractive

Робота напряму пов’язана з immediate UI responsiveness.

.userInitiated

User чекає результат для продовження flow.

.utility / .background

Longer-running або deferrable work, де latency менш критична.

QoS — сигнал scheduler-у про importance / latency expectations. Це не reserved thread і не reserved CPU core.

06 · DispatchGroup

Fan-out / fan-in для кількох asynchronous GCD operations

let group = DispatchGroup()

queue.async(group: group) { loadA() }
queue.async(group: group) { loadB() }

 group.notify(queue: .main) {
    renderFinishedState()
}

Group не задає queue semantics. Він просто дозволяє відслідковувати completion набору work items як одного unit.

07 · Barrier

Concurrent reads + exclusive writes

final class Store {
    private let queue = DispatchQueue(label: "store", attributes: .concurrent)
    private var values: [String: Int] = [:]

    func value(for key: String) -> Int? {
        queue.sync { values[key] }
    }

    func set(_ value: Int, for key: String) {
        queue.async(flags: .barrier) {
            self.values[key] = value
        }
    }
}
read A ━━━━━━━ read B ━━━━━━━ WRITE BARRIER ━━━━━ read C ━━━━━

Barrier чекає попередні items, виконується exclusive щодо інших items на цій custom concurrent queue, а наступні items починаються після нього.

08 · DispatchWorkItem

Encapsulated work + flags + cooperative cancellation state

let item = DispatchWorkItem {
    guard !DispatchWorkItem.currentIsCancelled else { return }
    doExpensiveWork()
}

queue.async(execute: item)
item.cancel()

Cancellation не магічно зупиняє executing code. Work має перевіряти cancellation state / бути спроєктований так, щоб завершитись cooperatively.

09 · Delayed execution
DispatchQueue.main.asyncAfter(deadline: .now() + 0.4) {
    showHint()
}

asyncAfter означає “не раніше приблизного deadline”. Це не real-time timer і не гарантія точної наносекунди виконання.

10 · Parallel CPU work

concurrentPerform — найбільш явний GCD tool для data parallelism

DispatchQueue.concurrentPerform(iterations: chunks.count) { index in
    process(chunks[index])
}

Intent

Iteration body незалежний; система може розподілити iterations між кількома workers і реально використати кілька CPU cores.

Still no hard guarantee

API не обіцяє N iterations = N threads = N cores. Actual degree of parallelism залежить від system resources і scheduler.

11 · What does .concurrent actually guarantee?

Permission for overlap, not physical simultaneity

let queue = DispatchQueue(label: "work", attributes: .concurrent)
queue.async { heavyA() }
queue.async { heavyB() }
.concurrent означає, що queue не серіалізує всі items один за одним. GCD може виконувати кілька items concurrently, але system-managed threads і OS scheduler визначають, чи буде реальний simultaneous execution на різних cores.
12 · Common failures

Deadlock

DispatchQueue.main.sync {
    // from main thread
}

Caller чекає queue, queue чекає caller.

Thread explosion / blocking

Багато blocking tasks на concurrent queues можуть змусити system створювати більше threads і погіршити performance.

Shared mutable state

Concurrent queue сама по собі не робить shared state safe. Потрібні serial confinement, barriers, locks або інша synchronization strategy.

Priority inversion

High-priority work може чекати resource, який утримує lower-priority work. QoS треба вибирати узгоджено.

Modern iOS rule of thumb: prefer Swift Concurrency for new asynchronous application code. GCD remains essential to understand because existing UIKit codebases, third-party APIs, locks/queues, callbacks and lower-level synchronization patterns still use it heavily.
15 · Interview recap

Queue ≠ thread

Queue describes scheduling semantics; threads are managed by the system.

sync ≠ serial

sync means caller waits. Serial/concurrent is a property of queue behavior.

Concurrent ≠ guaranteed parallel

Multiple work items may overlap; physical simultaneous execution depends on resources and scheduling.
