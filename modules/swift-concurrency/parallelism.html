Concurrency ≠ Parallelism

Concurrency означає, що кілька задач можуть бути in progress в один проміжок часу. Parallelism означає, що два шматки CPU work фізично виконуються одночасно — наприклад, на різних worker threads / CPU cores. Swift Concurrency дає structured way організувати tasks; фактичне розміщення jobs на threads вирішує runtime.

async let TaskGroup @concurrent generic executor CPU-bound work
01 · Mental model

Одночасно “в процесі” чи одночасно “на CPU”?

Network calls — чудовий приклад concurrency, але вони не доводять CPU parallelism: більшу частину часу task suspended і не займає thread.

Concurrent, але не обов’язково parallel

Два tasks можуть interleave на одному executor/thread: A виконується, suspend-иться, потім B, потім знов A.

Parallel

Дві CPU-bound jobs runnable одночасно й runtime має кілька worker threads — тоді вони можуть реально виконуватися одночасно.

Візуально

Worker 1
CPU work A
Worker 2
CPU work B
Це і є actual parallel execution. Але Swift не обіцяє, що A завжди піде на “thread 4”, B на “thread 7”, або що вони будуть pinned до конкретних cores.
02 · Concrete example

CPU-heavy tasks, які можуть бігти паралельно

У Swift 6.2 @concurrent явно відриває async function від caller actor і виконує її на generic executor. async let створює дві structured child tasks.

@concurrent
func countPrimes(upTo limit: Int) async throws -> Int {
    var count = 0

    for number in 2...limit {
        if number.isMultiple(of: 4_096) {
            try Task.checkCancellation()
        }

        if isPrime(number) {
            count += 1
        }
    }

    return count
}

func calculate() async throws -> (Int, Int) {
    async let first = countPrimes(upTo: 900_000)
    async let second = countPrimes(upTo: 1_000_000)

    return try await (first, second)
}
Що тут відбувається: async let створює двох siblings; обидва викликають @concurrent CPU-bound work на generic executor. Якщо є доступні worker threads/cores, runtime може виконувати ці jobs фізично паралельно.
03 · Counterexample

async let сам по собі не означає parallel

Actor isolation може навмисно серіалізувати роботу. Structured child tasks не обходять правила isolation.

Serialized on MainActor
@MainActor
func expensiveA() -> Int {
    heavySynchronousWork()
}

@MainActor
func expensiveB() -> Int {
    otherHeavyWork()
}

@MainActor
func run() async -> (Int, Int) {
    async let a = expensiveA()
    async let b = expensiveB()

    return await (a, b)
}
Eligible for parallel execution
@concurrent
func expensiveA() async -> Int {
    heavySynchronousWork()
}

@concurrent
func expensiveB() async -> Int {
    otherHeavyWork()
}

func run() async -> (Int, Int) {
    async let a = expensiveA()
    async let b = expensiveB()

    return await (a, b)
}
Ключ: parallelism потребує не лише кількох tasks, а й execution context, який дозволяє кільком jobs виконуватись одночасно. Один actor executor гарантує serial access до actor-isolated work.
04 · async let vs TaskGroup

Два способи зробити fan-out

Вибір між ними — про форму structured concurrency, а не про “рівень parallelism”.

async letКоли кількість незалежних child operations відома під час написання коду. Наприклад: profile + feed.
TaskGroupКоли кількість child tasks динамічна: масив images, files, chunks, IDs тощо.
ActorДає isolation і serial execution для actor-isolated jobs. Не інструмент для CPU parallelism усередині одного actor.
@concurrentSwift 6.2+: явний спосіб сказати, що async function повинна виконуватись поза caller actor на generic executor.
05 · Dynamic fan-out

Parallel candidates через TaskGroup

Цей pattern корисний для CPU-bound batch work. Не створюй тисячі heavy jobs без bounded concurrency — overhead і contention можуть зробити все повільнішим.

@concurrent
func process(_ chunk: Chunk) async throws -> ResultChunk {
    try Task.checkCancellation()
    return expensiveTransform(chunk)
}

func processAll(_ chunks: [Chunk]) async throws -> [ResultChunk] {
    try await withThrowingTaskGroup(of: ResultChunk.self) { group in
        for chunk in chunks {
            group.addTask {
                try await process(chunk)
            }
        }

        var results: [ResultChunk] = []
        for try await result in group {
            results.append(result)
        }
        return results
    }
}
Production nuance: для великого масиву краще обмежити кількість одночасно runnable CPU tasks приблизно до корисного рівня parallelism, замість blind fan-out на кожен item.
06 · Interview answer

Як це пояснити за 30 секунд

Concurrency is about task structure; parallelism is about physical execution. async let and TaskGroup let me start independent child tasks concurrently. If those tasks contain CPU-bound work that is allowed to run on the generic concurrent executor — for example via @concurrent in Swift 6.2 — the runtime may schedule them on different worker threads and they can execute in parallel. But Swift Concurrency does not guarantee a particular thread or CPU core, and actor-isolated work remains serialized by that actor's executor.
07 · Remember

Чотири правила

1async/await не означає background thread.
2async let / TaskGroup створюють concurrent child tasks, але самі по собі не гарантують physical parallelism.
3CPU-heavy independent jobs на generic concurrent executor можуть реально виконуватись паралельно, якщо runtime має доступний parallel capacity.
4Не покладайся на thread identity. Думай в термінах tasks, isolation, executors і suspension points.
