Concurrency vs Parallelism

Concurrent не означає guaranteed parallel.

Swift Concurrency дозволяє описати незалежну роботу як tasks. Runtime може виконувати її фізично одночасно на кількох worker threads / CPU cores, але API не дає контракту «Task A обов’язково на Core 1, Task B обов’язково на Core 2».

01 · Three concepts

Не плутай concurrency, parallelism і asynchrony

Concurrency

Кілька operations мають overlapping lifetime і можуть прогресувати незалежно.

Parallelism

Дві або більше operations фізично виконуються одночасно, зазвичай на різних CPU cores.

Asynchrony

Caller може suspend / продовжити іншу роботу замість блокування thread під час очікування.

02 · async let

async let створює concurrent child tasks — не hard parallel guarantee

@concurrent
func render(_ image: Image) async -> Image {
    // CPU-heavy independent work: resize, filters, pixel transforms…
    heavyRender(image)
}

async let first = render(imageA)
async let second = render(imageB)

let (a, b) = await (first, second)

Що ми отримали

first і second — незалежні child tasks. Якщо generic executor має доступні workers, їх CPU fragments можуть реально overlap у часі.

Чого ми не отримали

Немає гарантії конкретної кількості threads, конкретного core assignment або того, що обидві operations стартують в одну наносекунду.

Possible runtime execution: Core / worker 1 render(A) ━━━━━━━━━━━━━━━ Core / worker 2 render(B) ━━━━━━━━━━━━━━━ ↑ overlap Also legal: Worker 1 render(A) ━━━━━━━ render(B) ━━━━━━━ The scheduling choice belongs to the runtime / OS.
03 · CPU-heavy independent jobs

Чому саме такий приклад показує parallelism найкраще

CPU-bound

Image processing, compression, cryptographic calculations, large data transforms, expensive sorting / calculations. CPU реально зайнятий роботою.

I/O-bound

Network request, disk read, timer. Tasks можуть бути concurrent, але значну частину часу suspended і просто чекають зовнішню подію.

Independent означає, що B не потребує результату A. Якщо B = calculateB(using: await A), dependency сама робить parallel execution цієї пари неможливим.
04 · Actor serialization

Два tasks можуть бути concurrent і все одно не виконуватись паралельно

@MainActor
func updateA() { heavyWorkA() }

@MainActor
func updateB() { heavyWorkB() }

async let a: Void = updateA()
async let b: Void = updateB()
await (a, b)

Обидві child tasks існують concurrently, але actor-isolated fragments повинні проходити через один serial executor. Тому isolated CPU work серіалізується.

MainActor executor: updateA ━━━━━━━━━━━ updateB ━━━━━━━━━━━
05 · @concurrent

@concurrent — explicit off-actor execution, не «allocate me a core»

@concurrent
func heavyIndependentWork() async {
    // Runs as concurrent/off-actor work on the generic executor.
    // Runtime still chooses worker/thread/core scheduling.
}

Swift Concurrency навмисно абстрагує application code від thread identity. Thread після suspension може бути іншим, а кількість workers адаптується runtime-ом.

06 · TaskGroup

Dynamic fan-out теж створює можливість parallel execution

let outputs = await withTaskGroup(of: Output.self) { group in
    for input in inputs {
        group.addTask {
            await transform(input)
        }
    }

    return await group.reduce(into: []) { $0.append($1) }
}

Task group корисний, коли кількість independent jobs визначається runtime-ом. Він не означає «N tasks = N cores».

07 · Can anything guarantee parallel cores?

Ні — не в контракті Swift Concurrency

Немає API

Немає Task(onCore: 3), немає гарантії окремого thread для task, немає hard guarantee одночасного execution двох довільних tasks.

Навіть нижче рівнем

Навіть якщо вручну створити native threads, остаточне рішення про scheduling на фізичних cores все одно належить OS scheduler.

08 · Swift Concurrency vs GCD

GCD concurrent queue теж не дає hard guarantee physical parallelism

let queue = DispatchQueue(label: "work", attributes: .concurrent)

queue.async { heavyA() }
queue.async { heavyB() }

.concurrent означає, що queue дозволяє concurrent execution. System-managed thread pool і OS scheduler визначають фактичний parallelism. DispatchQueue.concurrentPerform є найбільш явним GCD інструментом для data-parallel CPU work, але й він не обіцяє конкретну кількість cores.

Interview answer
Swift Concurrency provides concurrency, not a guarantee of physical parallelism. Independent work scheduled away from a serial actor can execute in parallel when runtime resources are available, but worker-thread and CPU-core assignment are implementation details controlled by the runtime and the OS scheduler.
