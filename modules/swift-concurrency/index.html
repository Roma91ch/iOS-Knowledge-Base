00 · Whole system

Swift Concurrency — це не лише Structured Concurrency

Tasks відповідають за асинхронну роботу та lifetime. Actors і Sendable — за безпечне переміщення та доступ до state. Strict checking перевіряє цю модель під час компіляції.

execution / ownership cancellation propagation isolation hop await / suspension
🌳 StructuredParent owns child lifetime
🎈 UnstructuredArchitecture owns Task handle
Swift Concurrencyasync work + ownership + isolation
🏝 ActorsIsolation domains for mutable state
🛡 SendableSafe transfer between domains
Основна ментальна модель Structured / unstructured описує ownership і lifetime tasks. Actor isolation / Sendable описує доступ до state. Strict concurrency описує рівень compile-time enforcement. Це три різні осі, які не слід змішувати.
01 · Swift evolution

Не просто «до Swift 6 / після Swift 6»

Language mode, strict checking, default actor isolation та async-function isolation — окремі механізми, які можуть змінюватися незалежно.

Критичне уточнення. Swift 6 language mode не означає автоматично, що весь код ізольований до MainActor. Default MainActor isolation — окреме compiler/build setting. Так само nonisolated означає відсутність actor isolation, а не «background thread».
Checking

Swift 5 language mode

Concurrency features уже працюють. Complete actor-isolation і Sendable checking можна поступово ввімкнути як warnings через strict-concurrency setting.

Task

Task inherits actor context

Task {} успадковує current actor isolation, priority і task-local values. Він не «успадковує поточний thread».

Safety

Fewer diagnostics ≠ different ownership

Structured і unstructured semantics уже існують. Відсутність complete checking лише дозволяє більшій кількості небезпечного коду пройти компіляцію.

Language

Swift 6 mode

Complete data-race safety checking стає частиною language mode: actor isolation та Sendable violations переходять у errors.

Default

Not universally MainActor

Без окремого default-isolation setting unannotated code не стає MainActor-isolated лише через Swift 6 mode.

Runtime

Compiler enforcement

Strict concurrency не є scheduler policy. Воно не закріплює кожен Task за main thread і не створює background queue.

SE-0466

Default actor isolation

Модуль може opt in до MainActor як default isolation, що спрощує single-threaded UI code.

SE-0461

Async isolation evolution

Нові правила роблять caller-isolation behavior більш явним і зменшують несподівані executor hops для nonisolated async functions.

Approachable

Sequential by default when configured

Мета — зберігати просту послідовну модель, а concurrency вводити там, де developer її явно виражає.

Неправильно: «У Swift 6 Task за замовчуванням виконується на MainActor». Правильно: Task {} успадковує isolation місця створення. Саме місце може бути MainActor-isolated через annotation, framework inference або module default-isolation setting.

03 · Task lifetime

Structured і unstructured — це різні правила володіння

Різниця не в тому, «паралельно чи ні», а в тому, хто відповідає за lifetime, completion, errors і cancellation.

ownership / completion cancellation propagation
Parent scope Не може вийти, доки structured children не завершились.
async let child Фіксована кількість результатів.
TaskGroup child Динамічна кількість робіт.
Parent cancellation автоматично позначає structured children як cancelled. Помилки й результати повертаються через lexical scope.
Calling scope Створює Task і може завершитися одразу.
Function returns Lexical scope закрито.
Task { … } Продовжує жити, доки не завершиться або його явно не скасують.
Task {} успадковує actor isolation, priority і task-local values, але його lifetime не прив’язаний до завершення функції, що його створила.
Порівняти structured та unstructured code
✓ Structured
func loadScreen() async throws -> Screen {
  async let profile = api.profile()
  async let feed = api.feed()

  return try await Screen(
    profile: profile,
    feed: feed
  )
}
Unstructured: потрібен явний owner
final class Loader {
  private var task: Task<Void, Never>?

  func start() {
    task = Task {
      await refresh()
    }
  }

  deinit {
    task?.cancel()
  }
}
Task {} не є child task lexical scope. Зберігай handle, якщо потрібно керувати cancellation або lifetime.
04 · Choosing a primitive

Task — не одна кнопка для всієї concurrency

Senior-level відповідь починається з lifetime і ownership: чи відома кількість children, чи потрібен dynamic fan-out, чи задача має пережити scope.

async let: fixed fork, implicit join

Use when: кількість child operations відома під час написання коду. Якщо не await-нути binding явно, Swift все одно завершує або скасовує його перед виходом зі scope.
Показати async let

async let feed = api.fetchFeed()

  profile: profile,
  feed: feed

Обидва виклики стартують як child tasks; suspension відбувається під час await результатів.

TaskGroup: dynamic fan-out, one structured scope

withThrowingTaskGroup
N child tasks
for try await result
Use when: кількість jobs визначається runtime-даними. Group не повернеться, доки всі children не завершаться.
Показати throwing task group 
let images = try await withThrowingTaskGroup(
  of: Image.self,
  returning: [Image].self
) { group in
  for url in urls {
    group.addTask {
      try await downloader.image(from: url)
    }
  }

  var result: [Image] = []
  for try await image in group {
    result.append(image)
  }
  return result
}
Порядок результатів — порядок завершення, а не порядок додавання. Якщо потрібен stable order, передавай index разом із result.

Task { }: unstructured, але context-aware

@MainActor method
Task inherits MainActor
Important: новий task успадковує actor isolation, priority і task-local state поточного task. Це inheritance isolation context, а не inheritance конкретного thread чи queue.
Показати owner-managed Task 
@MainActor
final class SearchViewModel {
  private var searchTask: Task<Void, Never>?

  func search(_ query: String) {
    searchTask?.cancel()

    searchTask = Task {
      do {
        let results = try await api.search(query)
        try Task.checkCancellation()
        self.results = results
      } catch is CancellationError {
        // expected
      } catch {
        self.error = error
      }
    }
  }
}
Handle дозволяє реалізувати latest-request-wins через явний cancel().

05 · Actor isolation

Actor — це isolation domain, не приватний thread

Actor серіалізує доступ до isolated state через executor. Він може виконуватися на спільному thread pool; safety походить від isolation, не від thread affinity.

isolation hop await / suspension
A
SearchStore actor

Захищає cache та in-flight requests.

M
@MainActor ViewModel

Захищає UI-observable state.

Не dedicated thread Default actors і tasks зазвичай використовують shared concurrency thread pool.
await = boundary marker Call може suspend, але ключове — він може перейти в інший isolation domain.
Sendable matters Значення, що перетинають domains, мають бути безпечними для передачі.

Actor reentrancy: data-race safe ≠ atomic across await

1
Actor reads state let balance = self.balance
2
await suspends method Actor executor вільний виконувати іншу роботу.
3
Another task changes state balance уже може бути іншим.
4
Original method resumes Не можна припускати atomicity через suspension point.
Показати actor reentrancy bug і fix
✕ Stale assumption across await
actor BankAccount {
  private var balance = 100

  func withdraw(_ amount: Int) async throws {
    guard balance >= amount else { return }

    try await fraudCheck()

    // balance could have changed
    balance -= amount
  }
}
✓ Revalidate after suspension
actor BankAccount {
  private var balance = 100

  func withdraw(_ amount: Int) async throws {
    try await fraudCheck()

    guard balance >= amount else { return }
    balance -= amount
  }
}
Actor гарантує відсутність одночасного mutable access, але не зберігає logical invariant автоматично через await.
Показати @MainActor isolation 
@MainActor
final class ProfileViewModel {
  private(set) var state: State = .idle

  func load() async {
    state = .loading

    do {
      let profile = try await service.profile()
      state = .loaded(profile)
    } catch {
      state = .failed(error)
    }
  }

  nonisolated func analyticsName() -> String {
    "profile"
  }
}
Позначай isolation вимогу статично. MainActor.run корисний як точковий bridge, але не заміна правильної моделі isolation.
06 · Cancellation

cancel() надсилає сигнал — він не вбиває task

Swift cancellation cooperative. Task має перевірити стан, дійти до cancellation-aware API або отримати cleanup через cancellation handler.

cancellation signal / propagation normal execution
parent.cancel() Позначає task cancelled
Child A Task.isCancelled
Child B try Task.checkCancellation()
Cooperative stop / cleanup
Flag, not kill CPU loop продовжить роботу, якщо не перевіряє cancellation.
Structured propagation Cancellation parent автоматично поширюється на child tasks.
Cleanup Для негайної реакції обгорни operation у withTaskCancellationHandler.
Показати cancellation-aware loop 
func process(_ items: [Item]) async throws -> [Output] {
  var result: [Output] = []

  for item in items {
    try Task.checkCancellation()
    result.append(try await transform(item))
  }

  return result
}
Перевіряй cancellation у довгих CPU loops та між великими chunks роботи.
Показати cancellation handler 
func waitForEvent() async throws -> Event {
  try await withTaskCancellationHandler {
    try await source.nextEvent()
  } onCancel: {
    source.stopWaiting()
  }
}
onCancel може викликатися паралельно з operation; cleanup повинен бути thread-safe.

Senior interview drill

Відповідай за 45–90 секунд

Спочатку сформулюй відповідь сам, потім відкрий картку й перевір distinctions.

Що саме робить concurrency «structured»?

Child tasks мають lexical parent scope. Parent не завершується, доки children не завершились; cancellation, priority, task-local context і errors мають передбачувану структуру.

Follow-up: async let vs TaskGroup?
Чим Task { } відрізняється від child task?

Task {} створює unstructured task: він успадковує current actor isolation, priority та task locals, але не прив’язаний lexical lifetime до функції.

Follow-up: як керувати його lifetime?
Коли Task.detached є виправданим?

Коли робота навмисно не повинна успадковувати actor context або task-local state. Не використовувати як generic «background queue» escape hatch.

Follow-up: які risks із non-Sendable captures?
Actor гарантує serial execution чи окремий thread?

Actor гарантує mutual exclusion для isolated state через executor. Default actors можуть виконуватися на shared concurrency thread pool; thread identity не є моделлю safety.

Follow-up: що таке actor reentrancy?
Чому data-race safety не гарантує logical atomicity?

Під час await actor method може suspend, а actor — виконати інший task. State може змінитися до resume, тому invariants потрібно revalidate після suspension.

Follow-up: як спроєктувати critical section?
Як працює Swift task cancellation?

Cooperative flag. Structured cancellation поширюється на children, але code має перевіряти Task.isCancelled, викликати checkCancellation() або використовувати cancellation-aware APIs.

Follow-up: коли потрібен cancellation handler?
Як дебажити «Task cancelled, але робота продовжується»?

Перевірити, чи task виконує CPU loop без checkpoints, чи underlying callback API підтримує cancel, чи cancellation handler зупиняє external work, і чи перевіряється flag перед side effect.

Follow-up: де поставити checkCancellation?
Що означає Sendable у Swift 6?

Це compile-time model для значень, які безпечно перетинають isolation domains. Mutable reference state зазвичай потребує actor isolation, synchronization або обережного ownership.

Follow-up: коли допустимий @unchecked Sendable?
Чи Swift 6 автоматично робить усі Task MainActor-isolated?

Ні. Swift 6 language mode вмикає strict data-race safety enforcement. Task {} успадковує isolation місця створення. Default MainActor isolation — окреме module setting, а не автоматична властивість будь-якого Swift 6 target.

Follow-up: чим setting відрізняється від @MainActor annotation?
Чому nonisolated не означає background thread?

nonisolated описує відсутність actor isolation. Thread identity не є частиною цього контракту. Execution залежить від async isolation rules, caller context та runtime scheduling.

Follow-up: що змінилося у Swift 6.2 async isolation?
Чому semaphore.wait небезпечний у async code?

Він блокує thread в очікуванні future work. Cooperative runtime розраховує на suspension, щоб threads залишались доступними для progress інших tasks.

Follow-up: як bridge-ити callback API?
