05A · Executors & runtime

Actor → Executor → Runtime → Thread: хто за що відповідає

Isolation визначає, де логічно має виконуватись код. Executor визначає правила виконання jobs. Swift Concurrency runtime координує scheduling, а фізичний thread — лише ресурс, на якому виконується черговий шматок job.

Головне розділення. Actor ≠ Executor ≠ Thread. Actor — isolation domain для state. Actor має serial executor, який забезпечує взаємне виключення для actor-isolated jobs. Executor не означає «один конкретний thread». Для default actors робота зазвичай отримує threads із globalConcurrentExecutor; custom executors можуть змінити execution semantics. «Scheduler» нижче — це концептуальна роль Swift Concurrency runtime, а не окремий public object, який треба створювати в app code.
actor / executor hop enqueue / execution await / suspension

Велика ментальна модель

1 · Call site / Task await store.save(), Task {}, Task.detached або звичайний async call.
2 · Isolation decision Compiler знає: конкретний actor instance, global actor, MainActor чи nonisolated context.
3 · Executor Actor isolation використовує SerialExecutor. Він визначає exclusive execution context і порядок actor jobs.
4 · Runtime / TaskExecutor Default generic work використовує globalConcurrentExecutor. Task executor preference або custom executor можуть змінити source of execution.
5 · Physical thread Runtime виконує job fragment на доступному thread. Після suspension continuation може продовжитись на іншому thread.
Читай flow так Cross-actor call не «передає thread» іншому actor. Поточний task доходить до isolation boundary, за потреби suspend-иться, continuation enqueue-иться на executor потрібного isolation domain, а runtime забезпечує фактичне виконання. Після await thread identity не є стабільною частиною контракту.

Три різні actor-моделі

actor MyActor Кожен instance — окремий isolation domain. Два MyActor() не ділять один «глобальний actor». Для default actor runtime створює його default serial-executor identity; actor не отримує dedicated thread.
@MainActor Це global actor: усі declarations з цією isolation ділять один global isolation domain. На Apple UI platforms його executor інтегрований з main executor / main thread, тому UI state природно ізолювати тут.
Custom global actor Тип, позначений @globalActor і conforming до GlobalActor, надає одну стабільну static shared actor instance. Annotation цього типу потім працює подібно до @MainActor.
Показати custom GlobalActor 
@globalActor
actor ImagePipelineActor: GlobalActor {
  static let shared = ImagePipelineActor()
}

@ImagePipelineActor
final class ImagePipeline {
  private var cache: [URL: Image] = [:]

  func image(for url: URL) async throws -> Image {
    // Isolated to ImagePipelineActor.shared.
    // Not MainActor and not a dedicated thread.
    ...
  }
}
@globalActor — attribute, який робить тип global-actor type; GlobalActor — protocol. Ключова властивість protocol — стабільна static shared actor instance.

Що відбувається при cross-actor call

Caller isolation Наприклад @MainActor або інший actor.
→
await actor.method() Crosses isolation boundary; task може suspend, а continuation enqueue-иться до target actor.
→
Target actor executor Actor-isolated body виконується з exclusive access до state. Після return caller відновлює потрібну isolation.
Всередині того самого actor Synchronous actor-isolated method можна викликати без await, бо caller уже має потрібну isolation.
Ззовні actor Навіть synchronous actor method стає asynchronous cross-actor access: caller пише await, щоб дозволити hop.
await ≠ guaranteed hop await позначає потенційний suspension point. Якщо isolation уже правильна або operation не suspend-иться, фізичного thread switch може не бути.

Task, Task.detached і executor context

Task {} Коли closure формується в actor-isolated context, вона успадковує цю actor isolation. Наприклад, Task усередині @MainActor method може синхронно звертатись до MainActor-isolated state.
Task.detached {} Навмисно відрізає actor isolation і task-local context. Якщо detached work треба назад на actor — зроби explicit hop, наприклад await MainActor.run { ... } або actor method call.
Task executor preference Починаючи зі Swift 6 API може задавати TaskExecutor preference. Це окрема вісь від actor isolation: serial executor відповідає за actor exclusivity, task executor — за execution source.
Показати Task inheritance та explicit hop
Actor context inherited
@MainActor
final class ViewModel {
  var title = ""

  func refresh() {
    Task {
      // Closure is MainActor-isolated.
      title = "Loading…"
      let value = await service.load()
      title = value
    }
  }
}
Detached: hop back explicitly
@MainActor
func refresh() {
  Task.detached {
    let value = await loadValue()

    await MainActor.run {
      updateUI(value)
    }
  }
}

nonisolated: isolation opt-out, не «background executor»

Swift 6.2 nuance. nonisolated статично забороняє функції напряму використовувати actor-isolated state, але execution semantics async-функції залежать від language/features. У Swift 6.2 з NonisolatedNonsendingByDefault звичайна nonisolated async function за замовчуванням має caller-executor behavior (nonisolated(nonsending) semantics). Якщо потрібно явно виконуватись concurrent/off-actor, використовуй @concurrent.
Sync nonisolated Немає actor hop усередині synchronous call. Функція просто не має права напряму торкатися isolated state.
Async Swift 6.2+ Caller-executor behavior не робить function actor-isolated статично. Це важлива різниця між «де зараз виконується» та «до якого state compiler дозволяє direct access».
Task inside nonisolated function Новий unstructured Task {} не успадковує динамічну caller actor isolation лише через те, що nonisolated(nonsending) function зараз виконується на caller executor.
Показати nonisolated + MainActor bridge + @concurrent 
@MainActor
final class ProfileViewModel {
  var status = "idle"

  nonisolated func analyticsName() -> String {
    // No direct access to MainActor-isolated 'status'.
    "profile"
  }

  nonisolated func reportLoaded() async {
    await MainActor.run {
      status = "loaded"
    }
  }
}

@concurrent
func heavyIndependentWork() async {
  // Explicitly runs off the caller's actor on the generic executor.
  ...
}
Якщо module має default MainActor isolation, declarations усередині explicit actor type все одно ізольовані до self actor, а не автоматично до MainActor.

Що реально відбувається з threads

1
Job starts on an executor Default generic work зазвичай отримує thread із global concurrent executor pool; MainActor має main-executor integration.
2
await suspends continuation Task не блокує thread просто очікуючи network/timer/інший async result. Thread може виконувати іншу роботу.
3
Continuation becomes runnable Runtime знову enqueue-ить її відповідно до required actor / executor context.
4
May resume on another physical thread Для default concurrent execution thread affinity не гарантується. Правильність має спиратися на isolation, а не thread ID.

45-second interview answer Actor — це isolation domain. Кожен звичайний actor instance має власну serial-executor identity, але не власний thread. Cross-actor call через await може suspend current task і enqueue continuation на executor target actor. Default execution використовує Swift global concurrent executor та його thread pool; MainActor — special global actor, інтегрований з main executor. Task {} може успадковувати lexical actor isolation, Task.detached — ні. nonisolated описує isolation contract, не background thread; у Swift 6.2 async nonisolated execution має додаткову caller-executor nuance, а @concurrent явно означає off-actor concurrent execution.
