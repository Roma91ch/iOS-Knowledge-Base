Algorithm Complexity

Big O — це про ріст, не секунди.

Big O допомагає описати, як змінюється кількість роботи або памʼяті, коли росте input. Нас цікавить не те, що код сьогодні виконався за 3 ms, а те, що станеться, коли N виросте у 100, 1 000 або 1 000 000 разів.

01 · Mental model

Що саме вимірює Big O?

Не реальний час на конкретному Mac. Ми описуємо форму росту роботи відносно розміру input.

Time complexity
Як росте кількість значущої роботи: comparisons, iterations, lookups, recursive calls тощо.
Space complexity
Як росте памʼять. На інтервʼю часто окремо уточнюють auxiliary space — додаткову памʼять понад сам input.

04 · Why not milliseconds?

Секунди змінюються. Growth class — ні.

Швидше hardware зсуває цифру, але не змінює форму росту алгоритму.

O(1)
1
Робота не залежить від N. На швидшому CPU вона просто стане ще трохи швидшою.
O(N)
N
У 100× більший input ≈ у 100× більше роботи, незалежно від конкретних milliseconds.
O(N²)
N²
У 100× більший input ≈ у 10 000× більше роботи. Саме тут hardware перестає “рятувати”.
05 · Simplification lab

Викидай те, що не впливає на ріст.

Константи і non-dominant terms зникають, але незалежні variables залишаються.

O(2N + 10)
O(N)
2 і 10 — constants. Коли N росте, вони не змінюють growth class.
06 · Multiple inputs

N і M не можна просто зліпити в N.

Два незалежні inputs — дві незалежні dimensions. Послідовні loops додаються, nested loops множаться.

for value in arrayA {\n    use(value)\n}\n\nfor value in arrayB {\n    use(value)\n}
O(N + M)Проходимо N елементів, потім M елементів. Робота додається.
07 · Time vs Space

Один алгоритм має дві complexity.

Не зупиняйся після time complexity. Запитай себе: що я алокую залежно від N?

Set lookup solution

Один pass по array і зберігаємо побачені values.

Time O(N) · Space O(N)

Two nested loops

Порівнюємо багато пар, але не створюємо структуру, що росте з N.

Time O(N²) · Space O(1)

Recursive call stack

Навіть без array/dictionary recursion може споживати stack proportional to depth.

Space може бути O(N)
08 · Important nuance

Big O і “worst case” — не одне й те саме.

Це корисна точність: на інтервʼю shorthand часто спрощують, але ти маєш розуміти формальну картину.

ТехнічноBig O — asymptotic upper bound. Можна говорити про Big O конкретної worst-case, average-case або іншої функції.
У практиці інтервʼюКоли питають “What’s the Big O?”, часто очікують worst-case time complexity, якщо не сказано інакше.
Quick Sort exampleAverage/expected behavior: Θ(N log N). Worst case: Θ(N²). Краще називати case явно.
09 · Four-step routine

Як аналізувати код без паніки.

Одна коротка процедура працює для більшості interview-style задач.

1Назви inputsN, M, number of nodes, edges, characters тощо.
2Знайди repeated workLoops, recursion, branching, nested traversal.
3Запиши raw growthНапр. 2N² + 100N + log M.
4СпростиDrop constants і non-dominant terms; independent variables лишаються.

Practice mode

Визнач complexity сам.

Вибери відповідь. Тут важливіше пояснити чому, ніж просто натиснути правильну кнопку.

read → trace → nameСпочатку уяви, як росте робота.

1 · Direct access

func first(_ a: [Int]) -> Int? {\n    a.first\n}

2 · Single pass

for value in values {\n    print(value)\n}

3 · Pair work

for a in values {\n    for b in values {\n        compare(a, b)\n    }\n}

4 · Halving

var n = values.count\nwhile n > 1 {\n    n /= 2\n}

5 · Two independent arrays

for x in a { use(x) }\nfor y in b { use(y) }

6 · Cross product

for x in a {\n    for y in b {\n        compare(x, y)\n    }\n}
