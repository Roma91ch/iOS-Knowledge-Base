Stack, heap, and process memory.

An interview-ready mental model for where Swift data lives, why lifetime matters, and why struct = stack / class = heap is useful only as a first approximation.

01 · Core definition

What are stack and heap?

The stack and the heap are two different regions of a process's virtual memory, used for different allocation and lifetime patterns.

A process does not directly reason in terms of raw physical RAM addresses. It works inside its own virtual address space. The operating system and hardware memory-management unit map virtual memory pages to physical memory as needed.

02 · Stack

Fast, scoped, call-oriented storage

The stack is mainly used for function call frames, parameters, return information, and short-lived local data. It follows a last-in, first-out discipline at the call-frame level.

Why it is fast

Allocation and deallocation are typically just adjustments of the stack pointer as functions are entered and exited. No general-purpose search for a free memory block is required.

Lifetime constraint

Stack storage works best when the compiler can prove that the value does not need to outlive its scope or call frame.

func calculate() -> Int {
    let a = 10
    let b = 20
    return a + b
}

// Conceptually, short-lived local state can live in the
// current call frame and disappear when the function returns.
03 · Heap

Dynamic storage with flexible lifetime

The heap is used for dynamically allocated data whose lifetime is not tied to one function call. Heap allocations can be created at one point in time and released much later.

Why it is flexible

Data can survive after the function that created it returns, and multiple references can point to the same allocation.

Why it costs more

General-purpose heap allocation requires bookkeeping and synchronization. Reference-counted Swift objects also incur retain/release work.

04 · Swift mental model

Do not memorize “struct = stack, class = heap” as a rule

Interview trap: a Swift struct is a value type, not a “stack type.” A class is a reference type, not merely a “heap type.” Semantics and storage location are related, but they are not the same concept.

Class instances generally require heap allocation because they have reference identity and can have lifetimes independent of a specific call frame. A local variable that references the class instance may itself be stored in a stack frame or register.

Value types can often be stored inline or on the stack, but that is not a universal guarantee. A struct can be stored as part of a heap-allocated object, inside heap-backed collection storage, captured by an escaping closure, or transformed by compiler optimizations.

struct Point {
    var x: Double
    var y: Double
}

final class Box {
    var point: Point

    init(point: Point) {
        self.point = point
    }
}

let box = Box(point: Point(x: 1, y: 2))

// Box has reference identity and its instance is heap allocated.
// Point is still a value type, but here its stored value lives
// inline as part of the Box object's storage.
05 · ARC and lifetime

Heap lifetime is not bound to lexical scope

Swift manages ordinary class-instance lifetime using Automatic Reference Counting. Retains increase ownership and releases decrease it; when the strong reference count reaches zero, the object can be deallocated.

06 · Full interview answer

A strong 30–45 second answer

“The stack and the heap are two different regions of a process's virtual memory, used for different allocation and lifetime patterns.

The stack is mainly used for function call frames, parameters, return information, and short-lived local data. It follows a LIFO model, and allocation and deallocation are very fast because they happen automatically as functions are entered and exited.

The heap is used for dynamically allocated data whose lifetime is not tied to a particular function call. Heap allocations can live for an arbitrary amount of time and require some form of lifetime management, such as ARC in Swift.

The operating system maps this virtual memory to physical memory such as RAM.”

07 · Swift follow-up

If they ask about structs and classes

“It's an oversimplification to say structs are always on the stack and classes are always on the heap. Classes generally require heap allocation because they have reference identity, while value types may be stored on the stack, inline inside another object, or optimized differently by the compiler.”
08 · Short version

15-second interview answer

“Stack and heap are regions of a process's virtual memory. The stack is optimized for short-lived, LIFO allocations such as function call frames, while the heap is used for dynamically allocated data with more flexible lifetimes.”
