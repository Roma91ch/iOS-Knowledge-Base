01 · layers

Від моделі до виконаної дії

Ці поняття живуть на різних рівнях. Найчастіша плутанина — називати моделлю всю систему або вважати агента просто «чатом із сильним промптом».

ПостачальникAnthropic, OpenAI, Apple та інші — організації або платформи, що пропонують моделі й продукти.
→
LLM / модельКонкретна навчена модель. Вона працює з мовою, кодом і структурою, але сама не натискає кнопки.
→
ЧатІнтерфейс «запит → відповідь». Може не мати автономності, інструментів чи доступу до файлів.
→
Агентна програмаClaude Code, Codex або інша agentic application: організовує контекст, правила, дозволи та цикл дій.
→
ІнструментиФайли, shell, Xcode, API, база даних, браузер. Вони виконують дію або повертають факти.
Найкоротша формула: модель генерує й міркує; агентна програма перетворює це на послідовну роботу; інструменти дають системі можливість щось дізнатися або зробити.
Модель

Не має власної волі чи доступу

Вона не «бачить ваш репозиторій» і не «запускає тест», доки програма не передасть їй контекст або не надасть tool.

Агент

Сесійний виконавець

Конкретна робоча сесія, що рухається до цілі: планує крок, викликає інструмент, дивиться на результат.

Agentic application

Програма-організатор

Продукт або runtime, у якому живе агент: історія, конфігурація, permission prompts, skills, MCP та інтерфейс.

02 · same model, different host

Claude Code і Claude Agent у Xcode

Вони можуть використовувати Claude-модель і спільний клас агентних можливостей, але середовище запуску визначає інтерфейс, доступний тулсет і продуктові функції.

Claude Code

Агентна програма Anthropic

  • Зазвичай запускається у Terminal або підтримуваному IDE.
  • Працює з репозиторієм, shell, git і вашими MCP-серверами.
  • Має власні можливості продукту: наприклад, Remote Control, teleport або CLI-сесії.
  • Може під’єднатися до Xcode через MCP і отримати Xcode tools.
Claude Agent у Xcode

Anthropic-агент, інтегрований Xcode

  • Xcode дає йому контекст проєкту та специфічні можливості IDE.
  • Доступний набір: build, tests, Simulator, Preview, debugger та дозволені команди.
  • UI, дозволи й Apple skills належать Xcode як host-середовищу.
  • Не слід очікувати, що продуктова функція Claude Code автоматично з’явиться у Xcode.
Висновок: Xcode інтегрує агентну програму / агентний runtime від Anthropic, а не просто надсилає запити до Claude LLM. Але це не робить Xcode-клієнт повною копією Claude Code.

Приклад: Remote Control

Це механіка керування сеансом Claude Code з іншого пристрою. Це не tool для написання коду, тому в Xcode Claude Agent його зазвичай немає.

product capability

Приклад: Xcode build

Це можливість host-середовища Xcode. Її може отримати Xcode Claude Agent безпосередньо або зовнішній Claude Code, якщо його під’єднати до Xcode через MCP.

03 · action

Agent loop: не один prompt, а повторюваний цикл

Агент не повинен «знати наперед» усю відповідь. Він послідовно збирає інформацію і перевіряє, чи зроблений наступний крок справді наближає до мети.

1. Зрозуміти цільЩо просить людина? Який контекст уже є? Які правила та межі застосовні?
2. Обрати діюВідповісти одразу, поставити уточнення, прочитати файл, зробити пошук або викликати інструмент.
3. Викликати toolПрограма виконує перевірений виклик і повертає структурований результат або помилку.
4. Оцінити результатАгент використовує нові факти: завершує задачу, робить наступний крок або чесно повідомляє обмеження.

Tool contract

Ім’я, опис, input schema, output schema, помилки й дозволи. Чіткий контракт зменшує помилки краще, ніж довгий prompt.

structured I/O

MCP

Стандарт, яким agentic application підключається до інструментів і джерел. MCP — «розетка», а не сам інструмент і не база знань.

protocol

Контроль людини

Дії з наслідками мають бути видимими: показати намір, попросити дозвіл, дати можливість скасувати або переглянути результат.

04 · knowledge

RAG: знайти знання перед тим, як просити модель відповісти

RAG не тренує модель на ваших документах під час запиту і не витягує готову відповідь. Він знаходить кілька релевантних уривків, які модель може прочитати у своєму контексті.

A · Заздалегідь

Підготовка / індексація

Документи, код, wiki, тікети
→
Логічні уривки + metadata: URL, назва, права
→
Embeddings: числовий відбиток змісту
Embedding — не «стиснений текст для читання людиною», а вектор, що дає системі можливість знаходити близькі за сенсом уривки.
B · Під час запиту

Retrieval → generation

Запит: «Чому refresh token відхиляється?»
→
Пошук найближчих уривків у векторному індексі
→
LLM отримує запит + top-K уривків + посилання
На виході retrieval: фрагменти й метадані. На виході LLM: пояснення, складене на основі цих фрагментів.

Коли RAG доречний

Велика текстова база знань: документація, політики, контракти, інструкції, приватний контент.

Коли потрібен API

Точні структуровані та актуальні факти: замовлення, календар, баланс, статус доставки. Тут краще SQL/API tool.

Як RAG і MCP перетинаються

MCP tool може ховати RAG усередині: агент викликає search documentation, а сервер сам робить embeddings і retrieval.

05 · recall

Перевір себе за дві хвилини

Не заучуй формулювання. Спробуй пояснити кожну відповідь своїми словами й додай приклад зі знайомого продукту.

Чим модель відрізняється від agentic application?
Модель генерує й міркує. Agentic application організовує сесію: передає контекст, застосовує правила й дозволи, дозволяє викликати інструменти та зберігає процес роботи.
Чому Claude Code і Claude Agent у Xcode не мають автоматично однаковий тулсет?
Бо тулсет визначається host-середовищем та конфігурацією. Claude Code має власні CLI-продуктові можливості; Xcode надає IDE tools. MCP дозволяє підключати додаткові можливості, але не робить інтерфейси ідентичними.
Що насправді повертає RAG до моделі?
Релевантні уривки тексту та метадані, а не готову відповідь. Модель використовує їх як тимчасовий контекст, щоб сформулювати відповідь.
Чим MCP відрізняється від RAG?
MCP — протокол інтеграції з tools і ресурсами. RAG — підхід до пошуку релевантного текстового контексту перед генерацією. Вони можуть працювати разом, але вирішують різні задачі.
